## 1. 指令介紹

### `/diff`：看 AI 改了什麼（免 `git add`，可按每一輪對話查看！）

當 AI 幫你新增或修改了檔案後，輸入 `/diff` 就能打開全螢幕差異檢視器（Diff Viewer），清楚標示出**綠色新增了哪幾行、紅色刪掉了哪幾行**。

#### 為什麼剛建的新檔案不用先 `git add` / `commit` 也能看前後差異？

因為 `/diff` 裡面有**三個分頁**（打開 `/diff` 後按 **`Tab`** 或 **`←` / `→`** 切換）：

| 分頁名稱 | 比對基準是什麼？ | 要不要先 `git add` / `commit`？ | 適合什麼時候看？ |
| :--- | :--- | :--- | :--- |
| **1. `All Changes`**（預設首頁） | 比對目前資料夾與 **Git 最後一次 Commit（`HEAD`）** 的差異 | 若是剛新建、還沒 Commit 過的檔案，整份檔案都會顯示為「全新綠色新增」 | 準備 Git Commit 前，檢查整個專案總共改了哪些檔案 |
| **2. `Per Turn`（每一輪對話）⭐** | **`agy` 自動記錄「每一輪對話前後」AI 改了哪幾行** | **完全不用！** 就算沒做 `git add` / `commit`，也能分開看第 1 輪和第 2 輪各自改了什麼 | **剛建好新檔案又請 AI 修改時，想單獨看剛剛那一輪改了哪幾行** |
| **3. `Commit Tree`** | 專案過去的 Git Commit 歷史樹狀圖 | 只顯示已經 Commit 過的歷史紀錄 | 回頭查以前某次 Commit 改了什麼 |

#### 完整操作範例：用 `Per Turn` 檢查 AI 第二輪多加了哪幾行

```text
# 步驟 1（第 1 輪對話）：先讓 AI 建立一份新筆記
請幫我建立 reading-notes.md，寫出 3 個讀書重點

# 步驟 2（第 2 輪對話）：再請 AI 修改這份筆記
請在 reading-notes.md 最下面新增一段「今日行動清單」

# 步驟 3：打開差異檢視器
/diff
```

- **打開 `/diff` 後怎麼操作？**
  1. 一進去預設在 **`All Changes`** 分頁（因為 `reading-notes.md` 還沒 Git Commit 過，這裡點進去會看到整篇都是綠字）。
  2. 按一下 **`Tab`**（或 **`→` 右方向鍵**）切換到 **`Per Turn`（每一輪對話）** 分頁！
  3. 你會看到清單分成兩輪對話：在最新那一輪的 `reading-notes.md` 上按 **`Enter`** 點進去，就會發現**只有剛剛步驟 2 新增的「今日行動清單」標示為綠色新增**！
  4. **進階密技**：在檔案差異畫面裡，把游標移到某一行按 **`c`**，還可以直接在該行寫修改意見（按 `Esc` 離開時選 **`Y`** 就會把意見送給 AI 重改）。

> [!TIP]
> 如果你想在第一個 **`All Changes`** 分頁也只看到步驟 2 的修改差異，只要在步驟 1 結束後先請 AI 幫你做一次 `git add reading-notes.md && git commit -m "初版筆記"`，之後步驟 2 改完再看 `All Changes`，就會跟這個 Commit 比對了！

### `/artifact`：看 AI 產出的計畫與文件

當你用過 `/plan` 請 AI 擬定計畫，想再次打開那份計畫書來看或審查時：

```text
# 步驟 1：先用 /plan 讓 AI 產出計畫書
/plan 幫我規劃一份週末閱讀計畫，存成 weekend-reading.md

# 步驟 2：打開審查面板閱讀或核准計畫
/artifact
```

- **結果**：開啟產出物（Artifact）審查面板（快捷鍵：`Ctrl+R`），可用 `←` / `→` 選擇 **`open`**（打開閱讀，裡面可按 `c` 留言或 `Ctrl+G` 用外部編輯器開啟）、**`approve`**（同意執行，快捷鍵 `y`）或 **`reject`**（拒絕修改，快捷鍵 `n`），最後按 `Esc` 返回對話。外部編輯器可在 [04 環境配置](../04-config.md#3-常用設定項目) 的 `editor` 設定。

---

### `/copy`：複製 AI 的回答

想把 AI 回答你的文字直接貼到別的地方（例如 Line、Email 或報告裡），可以先讓 AI 產出幾則回答，再實際體驗 `/copy` 的三種複製方式：

```text
# 步驟 1：先請 AI 寫第一段內容（這會成為「倒數第 2 則」回答）
請幫我寫一封 50 字以內、語氣禮貌的「感冒請假信」給老師

# 步驟 2：再請 AI 寫第二段內容（這會成為「最後一則」回答）
請幫我用 3 個條列點，寫出「早睡早起的三個好處」

# 步驟 3：用 /btw 在背景順手問一句翻譯（不打斷主對話）
/btw 「早日康復」的英文怎麼說？請給我 2 個常用說法

# 步驟 4：測試三種複製方式（每次執行後，可按 Cmd+V / Ctrl+V 貼到記事本驗證！）
/copy
/copy 2
/copy btw
```

- **結果與三種用法對照**：
  - **`/copy`**：把 AI **最後一則回答**（步驟 2 的「早睡早起好處」）複製到系統剪貼簿。
  - **`/copy 2`**：把 AI **倒數第 2 則回答**（步驟 1 的「感冒請假信」）複製到系統剪貼簿（數字可換成 `3`、`4` 等）。
  - **`/copy btw`**：把剛剛用 **`/btw` 問問題得到的回答**（步驟 3 的「早日康復英文」）複製到系統剪貼簿。

### `/open`：用編輯器打開檔案（需先設定預設編輯器）

想直接用編輯器打開 AI 剛剛寫好的 Markdown 檔案來看或修改，**第一次使用前必須先設定好外部編輯器（`editor`）**，否則會出現 `no editor configured, set $EDITOR or configure in /settings` 的錯誤提示。

#### 完整操作範例：從設定編輯器到開啟檔案

```text
# 步驟 1（首次使用必做）：先設定你要用哪個編輯器（二選一）
# 👉 方法 A：打開設定選單，找到「Editor」按 Enter 選擇（如 vim，或選 other… 輸入 code / nano）
/config

# 👉 方法 B：直接用中文請 AI 幫你寫入設定檔（最快！可依習慣改成 "code"、"nano"、"vim" 或 Mac 的 "open -a TextEdit"）
請幫我把 ~/.gemini/antigravity-cli/settings.json 裡的 editor 設定為 "nano"

# 步驟 2：先確認有一份測試筆記（如果前面還沒建過 reading-notes.md，先請 AI 建立）
請幫我建立 reading-notes.md，寫出 3 個讀書重點

# 步驟 3：用 /open 直接打開這份檔案！
/open reading-notes.md
```

- **結果**：`agy` 會呼叫你剛才設定的外部編輯器開啟 `reading-notes.md`。
- **常用編輯器設定值與離開方式**：
  | 設定的 `editor` 值 | 開啟的軟體 | 看完怎麼離開回到 `agy`？ |
  | :--- | :--- | :--- |
  | `"nano"` | 終端機簡易編輯器（推薦新手） | 按 **`Ctrl+X`** 即可離開 |
  | `"vim"` | 終端機 Vim 編輯器 | 先按 **`Esc`**，再輸入 **`:q`** 按 `Enter`（若有修改想不存檔離開輸入 `:q!`） |
  | `"code"` | VS Code 視窗 | 直接在 VS Code 視窗閱讀或關閉分頁 |
  | `"open -a TextEdit"` | macOS 內建「文字編輯」App | 直接在 Mac 視窗閱讀或關閉視窗 |

### `/codesearch`：搜尋資料夾裡的文字內容（並可對特定行留言給 AI）

筆記或程式碼檔案變多之後，想快速找出哪一個檔案寫到了某個關鍵字，甚至直接點開那一行留言請 AI 修改（別名：`/cs`、`/search`）：

```text
# 步驟 1：先請 AI 建立兩份測試筆記，裡面都提到「牛肉湯」
請幫我建立 tainan.md（寫 3 個台南景點與必喝牛肉湯）與 taipei.md（寫 3 個台北夜市與宵夜牛肉湯）

# 步驟 2：搜尋整個資料夾裡哪些檔案出現過「牛肉湯」
/codesearch 牛肉湯

# 步驟 3（進階篩選）：只搜尋檔名符合 tainan* 的檔案
/codesearch f:tainan* 牛肉湯
```

- **結果與面板操作快捷鍵**：
  - 輸入後會打開全螢幕 **Code Search** 搜尋面板，依檔案分組並高亮標示所有出現「牛肉湯」的段落。
  - **常用按鍵**：
    | 按鍵 | 功能說明 |
    | :--- | :--- |
    | **`↑` / `↓`** | 在各筆搜尋結果之間上下移動 |
    | **`←` / `→`** | 跳到上一個／下一個檔案群組 |
    | **`Enter`** | 在內建檢視器打開該檔案，並自動跳到符合的那一行 |
    | **`c`**（在內建檢視器內） | **超實用！** 在目前這一行加上留言註解（輸入完按 `Enter` 儲存，按 `Esc` 離開時選 **`Y`** 就會把「檔案＋行號＋你的修改意見」直接送給 AI 處理） |
    | **`Ctrl+G`** | 直接用你設定的外部編輯器（`editor`）打開該檔案的對應行號 |
    | **`Esc`** | 關閉面板回到對話框 |

### `/tasks`：查看與管理「背景工作（Background Tasks）」

#### 什麼東西會進到 `/tasks`？（對！按 `Ctrl+B` 丟到背景的就是它！）

當 AI 正在執行一個花時間的終端機指令時，畫面下方會提示你：**`Press ctrl+b to send a long task to the background`**。
只要你按下 **`Ctrl+B`**，這個指令就會被丟到**背景（Background）**繼續跑，把對話框還給你——而**被丟到背景的工作，就是用 `/tasks` 來查看與管理的！**

一共有三種東西會出現在 `/tasks` 裡：

| 來源 | 怎麼變成背景任務（Task）的？ | 例子 |
| :--- | :--- | :--- |
| **1. 你按 `Ctrl+B` 丟到背景的指令** | AI 執行終端機指令跑太久時，你手動按 **`Ctrl+B`** 把它移到背景 | 正在跑大檔案下載、倒數計時或長測試時按 `Ctrl+B` |
| **2. AI 自動放進背景的長期程式** | 你請 AI 啟動一個不會自己結束的服務，AI 自動在背景執行 | 啟動本地網頁伺服器（如 `python3 -m http.server`） |
| **3. 定時排程（`/schedule`）** | 你用 `/schedule` 設定的倒數計時器或週期任務 | `/schedule 10m 提醒我喝水` |

> [!NOTE]
> **一句話分清楚 `/tasks` 和 `/agents`**：
> - **`/tasks`**：管的是「**背景指令與排程**」（例如按 `Ctrl+B` 丟去背景的終端機指令、`/schedule` 計時器）。
> - **`/agents`**：管的是「**AI 子代理**」（例如派出去查資料的 `research` 分身）。

---

#### 完整操作範例 1：親手體驗「按 `Ctrl+B` 丟到背景 → 用 `/tasks` 查看與停止」

我們故意讓 AI 執行一個會倒數 60 秒的終端機指令，讓你親手按 **`Ctrl+B`** 把它丟進 `/tasks`！

```text
# 步驟 1：請 AI 執行一個會跑 60 秒的終端機指令（若跳出權限詢問，按 Enter 同意執行）
請幫我在終端機執行這個指令：for i in $(seq 1 60); do echo "目前進度：$i 秒"; sleep 1; done
```

1. **步驟 2（關鍵動作！按 `Ctrl+B`）**：
   當畫面上看到指令開始跑（提示 `Press ctrl+b to send a long task to the background`）時，直接按下鍵盤的 **`Ctrl+B`**！
   👉 你會發現對話框立刻恢復可以打字，而且狀態列會顯示目前有 **`1 task`** 在背景跑。
2. **步驟 3（輸入 `/tasks` 查看背景進度）**：
   在對話框輸入：
   ```text
   /tasks
   ```
3. **步驟 4（在 `/tasks` 面板裡看輸出紀錄與強制停止）**：
   - 用 **`↑` / `↓`** 選中剛剛那個 60 秒的任務，按 **`Enter`** 點進去，就能看到它還在背景一秒一秒印出 `目前進度：15 秒...`！
   - 看完後想提早關掉它：選中該任務按 **`K`**（Kill），或在對話框直接對 AI 說「`請幫我停止背景正在跑的任務`」，最後按 **`Esc`** 離開面板。

---

#### 完整操作範例 2：用 `/schedule` 設定定時任務，再到 `/tasks` 查看與取消

除了按 `Ctrl+B` 丟去背景的指令，`/schedule` 排程也會出現在 `/tasks`：

```text
# 步驟 1：先設定一個 10 分鐘後的定時提醒（它會在背景開始倒數）
/schedule 10m 提醒我起來喝杯水、動一動

# 步驟 2：打開 /tasks 查看這筆倒數中的排程
/tasks
```

- **結果**：在 `/tasks` 面板裡可以看到這筆排程正在背景待命；不想等 10 分鐘的話，直接選中它按 **`K`**（或請 AI 取消排程）就能刪掉。

#### `/tasks` 面板常用快捷鍵速查

| 按鍵 | 功能說明 |
| :--- | :--- |
| **`Ctrl+B`**（在對話畫面） | 將目前正在執行的終端機長指令**丟到背景（Background）**，轉入 `/tasks` 管理 |
| **`↑` / `↓`**（在 `/tasks` 內） | 上下移動選取背景任務 |
| **`Enter`**（在 `/tasks` 內） | 點進去查看該背景任務的**即時輸出紀錄（stdout logs）** |
| **`K`**（在 `/tasks` 內） | **強制停止（Kill）** 選中的背景指令或排程 |
| **`Esc`**（在 `/tasks` 內） | 返回上一層或關閉 `/tasks` 面板 |

## ✅ 動手練習：實際檢查與搜尋 Markdown 筆記

我們用一份簡單的 `reading-notes.md`（讀書筆記）來體驗「檢查差異、搜尋文字、複製內容」，**完全不寫程式**：

| 步驟 | 在對話框輸入 | 觀察重點 |
| :---: | :--- | :--- |
| **1** | `請幫我建立 reading-notes.md，寫出「時間管理」的 3 個練習重點` | 讓 AI 先建立好第一版讀書筆記 |
| **2** | `請在 reading-notes.md 最下面新增一段「我今天就能開始做的 2 個小習慣」` | 讓 AI 修改剛剛的 `reading-notes.md` |
| **3** | `/diff` | 打開差異檢視器，按 **`Tab`（或 `→`）切換到 `Per Turn` 分頁**再按 `Enter`，看看剛才第 2 步新增的段落是不是用綠色標示出來？（看完按 `Esc` 返回） |
| **4** | `/codesearch 習慣` | 搜尋資料夾裡哪些檔案提到了「習慣」這個詞 |
| **5** | `/copy` | 把 AI 最後一則回覆複製到剪貼簿，試著貼到你的記事本看看 |
| **6** | `/open reading-notes.md` | 用設定好的編輯器打開這份 Markdown 檔案（若尚未設定編輯器，先用 `/config` 將 `Editor` 設為 `nano` 或 `vim`） |
