# 07　Subagent 子代理

> ★★★ 深入　｜　[← 06 專案規範與規則](06-agents-md.md)　｜　[章節首頁](README.md)　｜　下一站：[08 權限設定與沙盒 →](08-permissions.md)

**這一站你會學到**：主代理和子代理的差別、怎麼呼叫子代理，以及如何用 **`/swarm`** 讓多個 AI 代理在共享留言板上平行分工與交叉檢查。

---

## 1. 什麼是 Subagent（子代理）？

在比較大的專案裡，如果讓同一個 AI 包辦所有事，對話視窗很快就會被大量的搜尋紀錄和檔案內容塞滿，讓 AI 開始忘東忘西、回應變慢。

**子代理（Subagent）** 就像主代理派出來的專門助手：
- **主對話不塞爆**：子代理在自己獨立的工作階段裡翻找幾十個檔案，最後**只把整理好的結論帶回來**給主代理。
- **權限更安全**：例如專門查資料的子代理只有「唯讀」權限，不會在探索時不小心改壞你的程式。
- **各司其職**：查程式碼、畫圖、寫安全規則都有各自專屬的助手。

---

## 2. 查看有哪些代理可以用

**方法一：在 `agy` 對話框裡輸入**

```text
/agents
```

會打開代理管理畫面，查看目前可用的代理與正在背景執行的子代理。

**方法二：在一般終端機執行**

```bash
agy agent
```

輸出範例（實際內容依環境與安裝的外掛而定）：

```text
Available agents:
research
image-generator
firestore-rules-author
```

啟動 `agy` 時，也可以直接指定這次要用哪個代理：

```bash
agy --agent research
```

## 3. 常見的內建子代理

| 代理名稱 | 專門做什麼 | 權限特色 |
| :--- | :--- | :--- |
| **`research`** | 查資料與探索專案。負責大範圍搜尋檔案、讀懂架構或整理文件 | **唯讀環境**，只看不改，不怕改壞程式 |
| **`self`** | 分身助手。繼承主代理的全部能力，適合在背景處理比較花時間的子任務 | 擁有和主代理相同的工具與模型 |
| **`image-generator`** | 依照需求產生或編輯圖片素材 | 專門產出圖片並回傳檔案路徑 |
| **`firestore-rules-author`** | Cloud Firestore 安全規則（`firestore.rules`）專家 | 專門撰寫與檢查安全規則 |

## 4. 怎麼呼叫子代理？

你不需要學特別的語法，用平常說話的方式就行：

1. **直接用中文點名**：
   ```text
   請派 research 子代理找出專案裡所有處理使用者登入的檔案，整理成清單給我。
   ```
2. **讓主代理自己決定**：
   當你交代一個需要先大量查資料的任務（例如「研究怎麼把這個套件升到最新版並評估影響」），主代理會自動派出 `research` 子代理去調查，收到報告後再幫你整理結果。

## 5. `/swarm`：平行代理協作團隊

當一個工作可以拆成好幾個**不會互相衝突的檔案、模組或問題**，或者你希望有另一個 AI 先幫你檢查改動並跑完測試時，可以使用 **`/swarm`**（目前為 Preview，支援 Google AI Pro 與 Ultra 方案）。

### 怎麼運作？協調者、工作代理與共享留言板

當你輸入 `/swarm <任務>` 時，目前的對話會變成團隊的**協調者（Coordinator）**，自動幫你組隊：

1. **拆工作、一人負責一塊**：協調者把任務拆開，指派給具名的工作代理（例如 `@date-tests`、`@currency-tests`）。如果多個代理需要同時改檔案，協調者可以給每個代理獨立的工作區副本（Workspace），不會互相蓋掉對方的檔案。
2. **公開任務簡報（Brief）**：每個工作代理都有乾淨的對話空間。協調者會在**共享留言板**貼出簡報，寫清楚每個人負責哪裡、哪裡不能動，以及怎樣算完成。
3. **專屬審查員（`@verifier`）**：通常每 2～4 位工作代理會配一位 `@verifier`。它不寫程式，專門看大家的 `/diff`、跑測試，發現問題就直接 `@` 負責的代理修好。
4. **共享留言板與休眠省額度**：所有進度、提問與測試結果都貼在留言板上。還在等別人回覆的代理會進入休眠（`waiting`），**休眠時完全不消耗額度**，直到有人在留言板 `@` 它的名字才會醒來繼續做。

> [!CAUTION]
> **注意額度消耗**：Swarm 裡的每位成員都是獨立的 AI 代理，消耗模型額度（Quota）的速度會比單一對話快很多。如果某位成員額度用完了，它會先暫停並提示你，不會無限重試；這時可以請協調者幫它換一個模型繼續做。

### 在終端機啟動與觀看 Swarm

#### 1. 啟動 Swarm

在輸入框打 `/swarm`，寫清楚目標和驗收方式：

```text
/swarm 為 src/utils/date.ts 與 src/utils/currency.ts 新增單元測試，並執行 npm test 確認全部通過
```

啟動後，對話框下方會出現 **Swarm 即時狀態列**，顯示目前的討論和誰正在工作。全部完成後，按 **`Alt+X`** 可以收起狀態列。

#### 2. 開啟全螢幕即時看板（Live Board）

輸入 **`/swarm board`** 或按快捷鍵 **`Alt+S`**（macOS 終端機需將 Option 設為 Meta/Alt 鍵），就能打開全螢幕看板，裡面有三個區塊：
- **Roster（成員名單）**：看誰在工作（`working`）、誰在待命（`waiting`）、用哪個模型。
- **Posts（貼文動態）**：留言板上的所有對話紀錄。
- **Message（訊息內容）**：完整顯示目前選中的貼文。

**看板常用按鍵：**

| 按鍵 | 功能 |
| :--- | :--- |
| `j` / `k` 或 `↓` / `↑` | 上下移動選取貼文、成員，或捲動內容 |
| `g` / `G` | 跳到第一則或最後一則 |
| `Tab` / `Shift+Tab` | 在 Roster、Posts、Message 三個窗格之間切換 |
| `Enter` 或 `Space` | 展開或收合選中的貼文與成員細節 |
| `f` | 開關自動跟隨最新貼文（Follow mode） |
| `p` | 只看選中成員的發言；再按一次 `p` 或 `Esc` 顯示全部 |
| `z` | 把目前的窗格放大到全螢幕，或還原 |
| `o` | 直接打開該成員的獨立對話視窗 |
| `q` 或 `Esc` | 離開看板，回到對話框 |

### 中途調整方向與批准權限

- **改方向**：直接跟主對話的協調者說，它會在留言板上通知大家。
- **私訊某位成員**：在輸入框用 `@` 點名（只會送給那個代理，不會貼上公開留言板）：
  ```text
  @verifier 請順便執行整合測試 npm run test:integration
  ```
- **快速處理權限詢問**：
  - 按 **`Alt+J`**：跳到下一個正在等你同意的子代理。
  - 按 **`Ctrl+K`**：不用切換畫面，直接同意狀態列上的子代理請求。

### `/swarm` 實用範例

| 情境 | 可以這樣寫 |
| :--- | :--- |
| **多個檔案一起加功能** | `/swarm 為 src/routes/users.ts、orders.ts、products.ts 三個 API 加上輸入驗證，每個檔案配一位 worker 並補上測試，最後由 verifier 執行 npm test。` |
| **不同模型交叉檢查** | `/swarm 為 pkg/httpclient 加上重試機制，請讓 verifier 用跟 worker 不同的模型檢查有沒有 race condition，並執行 go test -race ./...。` |
| **平行找 Bug 原因** | `/swarm 找出為什麼程式啟動要 4 秒。派三位唯讀 worker 分別檢查模組匯入、設定檔載入和外掛探索，在留言板比對證據後列出修改建議。` |
| **一次修好散落在各處的測試** | `/swarm 執行 pytest 找出所有失敗的測試，依資料夾分組，每組派一位 worker 修好（不可刪掉 assertion），最後由 verifier 重跑全部測試。` |

## 6. 大型長期專案：`/teamwork`

如果要做跨好幾個階段的大改版（例如整個網站換框架），需要先由 AI 訪談確認規格、再依里程碑一步步推進，可以輸入：

```text
/teamwork 把這個網站從 JavaScript 改寫成 TypeScript
```

（僅限付費方案。）

## 7. 怎麼選？Subagents、`/boost`、`/swarm` 與 `/teamwork`

| 比較項目 | Subagents（子代理） | `/boost` | `/swarm` | `/teamwork` |
| :--- | :--- | :--- | :--- | :--- |
| **什麼時候用** | 順手派一個小任務（如查資料、找檔案） | 很難的 Bug 或演算法，需要反覆深度思考 | 可以拆成好幾個獨立檔案或問題平行處理 | 全專案大改版、跨階段的長期工程 |
| **合作方式** | 子代理做完直接回報給主代理 | 多個代理從不同角度推理並交叉驗證 | 具名代理與審查員（`@verifier`）在留言板合作 | 先訪談定規格，再依里程碑與審核關卡推進 |
| **怎麼啟動** | 主代理自動派，或用中文點名 | `/boost <問題>` | `/swarm <任務>` | `/teamwork <目標>` |
| **花費時間** | 幾秒～幾分鐘 | 幾秒～幾小時 | 幾分鐘～幾小時 | 幾小時～幾天 |
