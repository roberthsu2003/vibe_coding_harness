**這一站你會學到**：主代理與子代理的協同機制、如何檢視與呼叫子代理，以及子代理如何保持上下文乾淨。

---

## 1. 什麼是 Subagent（子代理）？

在大型專案開發中，如果讓單一 AI 代理包辦所有事，主對話很快就會充斥著大量搜尋過程、零碎日誌與無關的檔案內容，導致 Token 爆量且推理品質下滑。

**子代理（Subagent）** 是主代理在需要時派發出去的專屬助手：
- **獨立的 Context**：在獨立的工作階段中運行，只把最終結論或產出帶回給主代理。
- **特定工具與權限隔離**：例如指派一個「只讀」的探索代理，不允許修改檔案。
- **分工更明確**：研究、架構審查、圖片生成或特定領域規則撰寫各司其職。

---

## 2. 檢視可用代理

在終端機中，可以隨時透過 `agy agent` 查看當前環境註冊的所有代理：

```bash
agy agent
```

輸出範例：

```text
Available agents:
research
image-generator
firestore-rules-author
```

在啟動 `agy` 時，也可以直接指定預設運作的代理角色：

```bash
agy --agent research
```

---

## 3. 常見的子代理角色

| 代理名稱 | 職責說明 | 權限特性 |
| :--- | :--- | :--- |
| **`research`** | 程式庫與專案研究。負責大範圍搜尋檔案、探索架構或整理技術文件 | 通常為唯讀環境，防止探索過程中意外改動代碼 |
| **`self`** | 繼承主代理設定的背景代理。適合在背景非同步執行長耗時子任務 | 具備完整工具鏈與相同模型設定 |
| **`image-generator`** | 針對 UI 設計需求生成或編輯圖形資產 | 專注圖形產出與路徑回傳 |
| **`firestore-rules-author`** | 專案安全規則（如 Firestore Security Rules）的專家代理 | 專門分析與強化安全規則防禦 |

---

## 4. 主代理如何調用子代理？

在與 `agy` 的對話中，你不需要手動編寫繁瑣的代理調度程式，主代理具備自主分工能力：

1. **直接指派任務**：
   ```text
   請派 research 代理去調查目前專案中所有使用到 deprecated API 的位置，並整理成清單。
   ```
2. **自動協同**：
   當你要求「深入研究一個新套件的整合方式並提供重構評估」時，主代理會自動調用 `invoke_subagent` 委派研究任務，研究完成後自動接手成果並在主視窗中呈現。

---

## 5. 多代理模式（Teamwork）

如果想讓多個代理平行協同作業，可在對話中輸入斜線指令：

```text
/teamwork
```

這會引導主代理拆分任務樹，協調多個子代理同時進行模組撰寫、單元測試補齊與自動審查（Auto-review），顯著加快大型功能的交付進度。
