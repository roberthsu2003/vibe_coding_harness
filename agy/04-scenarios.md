# 04　實戰情境

**這一站你會學到**：處理即時中斷、壓縮超長對話、使用規劃模式、以及撰寫高品質 Prompt 的技巧。

---

## 情境 A：AI 正在執行，想中斷並補充條件

在 agent 正在調用工具、搜尋檔案或修改程式碼時：
1. 按下 **`Ctrl+C`** 即可中斷當前工具執行或輸出。
2. 在輸入框補充漏掉的要求，例如：
   ```text
   剛才中斷是因為登入 API 還需要支援 JWT Refresh Token，請把這個需求一併加入設計。
   ```
3. 按 `Enter` 送出，AI 會接續先前的狀態繼續進行。

---

## 情境 B：對話累積過長，AI 回覆變慢

當對話進行了多個輪次、翻閱了數十個檔案後，Context Window 可能會被歷史日誌填滿。

| 情況 | 建議做法 |
| :--- | :--- |
| **繼續進行當前任務** | 輸入 **`/compact`**。agy 會將前面的討論提煉為結構化摘要，釋放大量的 Context 空間。 |
| **準備開始全新的任務** | 結束目前對話並開新對話：退出後重新啟動 `agy`，或指定新的專案/工作階段。 |
| **接續先前的特定工作階段** | 啟動時加上 `-c`（`--continue`）接續最近的對話，或 `--conversation <ID>` 指定歷史階段。 |

---

## 情境 C：面對龐大架構或跨檔案改動

不要直接要求 AI「重構整個後端」，而是先利用 **Plan 模式**：

1. 輸入 **`/plan`** 或在啟動時指定 `agy --mode plan`。
2. 讓 AI 先列出架構步驟、風險評估與檔案清單。
3. 你可以 review 計畫，要求修改步驟：
   ```text
   請把資料庫 migration 移到第三步，先不要移除舊的 API 欄位以保持向下相容。
   ```
4. 審查完成後再切換回執行模式，讓 AI 逐步落實。

---

## 情境 D：無人值守的深度目標執行

如果你希望 AI 徹底排查完一個困難的 Bug，即便遇到測試失敗也自動循環修復：
- 使用 **`/goal`** 指令，AI 會自主設定驗證迴圈，主動重複「分析 → 改代碼 → 跑測試 → 查看日誌 → 修正」，直到目標完全達成。

---

## 撰寫高品質 Prompt 的三要素：目標、範圍、驗收

| 要素 | 說明 | 示範 |
| :--- | :--- | :--- |
| **目標（Goal）** | 明確要達成的業務或技術目的 | 為購物車 API 加上折扣碼驗證邏輯 |
| **範圍（Scope）** | 規定可修改與不可修改的邊界 | 僅修改 `src/cart/`，不要變更 `src/payment/` 的介面 |
| **驗收（Verification）** | 給出客觀可驗證的標準 | 執行 `uv run pytest tests/test_cart.py` 且覆蓋率高於 90% |

**組合後的標準 Prompt 範例：**

```text
請為購物車模組新增折扣碼（Coupon Code）驗證邏輯。
範圍：
- 主要修改 src/cart/service.py 與 src/cart/models.py
- 不要修改 src/payment/ 底下的任何介面以確保向下相容
驗收條件：
- 在 tests/test_cart.py 新增三種情境（無效碼、過期碼、滿額折抵）的測試
- 執行 uv run pytest tests/test_cart.py 全部通過
```
