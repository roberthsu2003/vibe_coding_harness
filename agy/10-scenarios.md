# 10　實戰情境

> ★★ 進階　｜　[← 09 指令模式與 Herdr](09-cli-run.md)　｜　[章節首頁](README.md)　｜　📚 [維護指令與疑難排解](reference.md)

**這一站你會學到**：AI 做到一半想補充、改壞了想退回、對話太長變慢時怎麼辦，以及怎麼用「目標、範圍、驗收」把需求說清楚。

---

## 情境 A：AI 正在工作，才想到漏講了條件

看情況有三種做法：

1. **想等它做完這一輪再接著做（最常用）**：
   直接在輸入框打字並按 `Enter`。訊息會先排隊（Queue），等 AI 完成手上的步驟就會馬上處理。
2. **它已經走錯方向，想馬上喊停**：
   按 **`Ctrl+C`**（或 **`Esc`**）中斷目前的動作，然後輸入補充說明：
   ```text
   剛才停下來是因為登入 API 還需要支援 Refresh Token，請把這個需求一起加進來。
   ```
3. **只是順便問個小問題，不想打斷它**：
   用 **`/btw`** 提問，AI 回答完不會干擾正在做的主任務：
   ```text
   /btw pytest 的 -k 參數怎麼用？
   ```

---

## 情境 B：AI 越改越亂，想退回重來

1. 按 **`Ctrl+C`** 讓 AI 先停下來。
2. 輸入 **`/rewind`**（或 `/undo`），從清單選擇還沒改壞前的那一則訊息，把對話退回那個時間點。
3. 輸入 **`/diff`** 或 `!git status` 檢查檔案狀態（必要時用 `git checkout -- <檔案>` 還原檔案）。
4. 把需求寫得更明確一點，再重新送出。

---

## 情境 C：想試另一種做法，又怕弄亂原本的對話

輸入 **`/fork`**（或 `/branch`）複製一份目前的對話，在新的對話裡放心嘗試。如果覺得新做法不好，輸入 **`/resume`** 就能切換回原本的對話。

> [!WARNING]
> `/fork` 只會複製**對話紀錄**，不會複製你的程式碼檔案。如果要連檔案一起隔開，請搭配 [Git 分支或 Worktree](../worktree/README.md)。

---

## 情境 D：對話太長，AI 回應變慢或開始忘東忘西

當你跟 AI 聊了好幾十輪、讀了一大堆檔案後，對話空間（Context）會被塞滿。可以先用 `/context` 檢查用量，再依情況處理：

| 情況 | 建議做法 |
| :--- | :--- |
| **還在做同一件事** | 輸入 **`/compact`**，把前面的對話濃縮成重點摘要，騰出空間繼續做 |
| **已經做完，要換新任務** | 輸入 **`/clear`**（或 `/new`）清空畫面，開始乾淨的新對話 |
| **想找回昨天的對話繼續做** | 輸入 **`/resume`** 從清單選取；或啟動時用 `agy -c` 接續最近一次對話 |

---

## 情境 E：要改很多檔案，怕 AI 一口氣改壞

不要直接叫 AI「幫我重構整個後端」，先用 **Plan（規劃）模式**：

1. 輸入 **`/plan 你的需求`**（或按 `Shift+Tab` 切到 `plan` 模式）。
2. AI 只會讀檔案，然後寫出一份修改計畫給你審閱。
3. 覺得哪裡不妥，直接用中文請它調整計畫：
   ```text
   請先不要改資料庫的欄位名稱，第一階段只加新的 API 就好。
   ```
4. 確認計畫沒問題並同意後，AI 才會真正開始動手改檔案。

---

## 情境 F：想讓 AI 自己修到測試全部通過為止

如果專案已經有完整的測試，想讓 AI 自己重複「改程式 → 跑測試 → 看錯誤 → 再修正」直到全部通過：

```text
/goal 修好 tests/ 裡所有失敗的測試，直到 uv run pytest 全部通過
```

> 跑 `/goal` 前記得先 `git commit` 備份目前的進度。

---

## 把需求說清楚：目標、範圍、驗收

跟 AI 交代任務時，不用寫得像論文一樣長，只要在心裡確認這三件事：

| 要素 | 問自己一句話 | 範例 |
| :--- | :--- | :--- |
| **目標（Goal）** | 要做什麼？ | 為購物車加上折扣碼驗證功能 |
| **範圍（Scope）** | 改哪裡？哪裡不能動？ | 只改 `src/cart/`，不要動到 `src/payment/` |
| **驗收（Verification）** | 怎樣算做完？ | 補上單元測試，並執行 `uv run pytest` 全部通過 |

**合起來就是一段清楚好懂的指示：**

```text
請幫購物車模組加上折扣碼（Coupon Code）驗證功能。
範圍：
- 只修改 src/cart/ 底下的檔案
- 不要修改 src/payment/，確保原本的結帳流程不受影響
驗收：
- 在 tests/test_cart.py 補上有效碼、過期碼、無效碼三種測試
- 執行 uv run pytest tests/test_cart.py 確認全部通過
```

> [!TIP]
> 一開始想不清楚細節也沒關係！可以用 **`/grill-me 我想做...`**，讓 AI 主動一個一個問題訪問你，幫你把需求釐清。
