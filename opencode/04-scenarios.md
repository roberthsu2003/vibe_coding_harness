# 04　實戰情境

> ★★ 進階　｜　[← 03 AGENTS.md](03-agents-md.md)　｜　[章節首頁](README.md)　｜　下一站：[05 Subagent 子代理 →](05-subagents.md)

**這一站你會學到**：AI 做到一半想補充、改錯了想復原、對話太長變遲鈍時怎麼辦，以及怎麼寫出好的 prompt。

---

## 情境 A：AI 正在做，才發現漏交代了需求

1. 按 **`Esc`**，AI 會停下來。
2. 在輸入框補充，例如：「剛才中斷是因為還要加上錯誤處理，請連同剛才的進度一起完成」。
3. 按 `Enter` 送出，AI 會接著做。

## 情境 B：AI 越改越糟

1. 按 **`Esc`** 中斷。
2. 輸入 **`/undo`**，復原上一則訊息和它改過的檔案。可以連續執行好幾次。
3. 輸入 `!git status` 確認檔案已經恢復。

> 想把剛才的復原再做回來：`/redo`。

## 情境 C：對話太長，AI 開始忘東忘西

| 情況 | 做法 |
| :--- | :--- |
| 還在做同一件事 | `/compact`：把前面的對話整理成摘要，騰出空間 |
| 要開始新任務 | `/new`：開新對話（舊對話可以用 `/sessions` 找回） |

## 情境 D：剛 commit 完才發現漏了東西

直接請 AI：

```text
剛才的 commit 漏掉了 X，請修改後用 git commit --amend 合併進前一個 commit。
```

> ⚠️ `--amend` 只適合**還沒 push** 的 commit。

## 寫出好 prompt 的三要素：目標、範圍、驗收

| 要素 | 說明 | 範例 |
| :--- | :--- | :--- |
| **目標** | 要做什麼 | 新增使用者登入的單元測試 |
| **範圍** | 可以改哪裡、不能改哪裡 | 只修改 `tests/test_auth.py`，不要改程式本身 |
| **驗收** | 怎樣算完成 | `uv run pytest` 全部通過 |

合起來就是：

```text
請新增使用者登入的單元測試。
範圍：只修改 tests/test_auth.py，不要改動程式本身。
驗收：執行 uv run pytest，全部測試都要通過。
```
