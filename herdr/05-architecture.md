# 05　底層原理：為什麼關掉視窗，AI 還在跑？

> ★★★ 深入　｜　[← 04 實戰情境](04-scenarios.md)　｜　[章節首頁](README.md)　｜　下一站：[06 多 Agent 協同 →](06-supervisor-subagent.md)

**這一站你會學到**：Client／Server 架構、Daemon（背景常駐程式）、PTY（虛擬終端）三個概念。不懂也能用 Herdr，懂了會更清楚它為什麼這樣設計。

---

## 1. 一張圖看懂：螢幕和主機是分開的

| 類型 | 生活比喻 | 關掉視窗時 |
| :--- | :--- | :--- |
| **一般終端機** | 掌上型遊戲機：螢幕和主機黏在一起 | 程式跟著一起結束，進度消失 |
| **Herdr** | 電視（Client）＋遊戲主機（Server），兩者分開 | 只關掉電視，主機繼續跑；再打開就接回原畫面 |

![Herdr Client/Server 架構圖](assets/herdr-client-server-arch.svg)

| 名詞 | 白話 | 負責什麼 |
| :--- | :--- | :--- |
| **Client** | 電視螢幕 | 把畫面畫出來、接收你的鍵盤和滑鼠 |
| **Server** | 遊戲主機 | 真正執行每個窗格裡的程式和 AI |
| **Unix Domain Socket** | 電視和主機之間的連接線 | 在同一台電腦內快速傳遞按鍵和畫面 |

按 `prefix+q` 暫離、關掉終端機、SSH 斷線時，**關掉的只有 Client**。Server 和裡面的 AI 繼續工作，再輸入 `herdr` 就把「螢幕」接回「主機」。

---

## 2. Daemon：在背景值班的程式

一般程式（瀏覽器、編輯器）都有視窗，關掉視窗程式就結束。**Daemon 沒有自己的視窗，專門在背景值班**，就像手機的鬧鐘：螢幕關了，時間到還是會響。

`herdr server` 就是 Herdr 的 Daemon：

- **需要時才啟動**：開機時不會自動執行。第一次輸入 `herdr` 時，它才在背景啟動。
- **本身很輕量**：實測整個 server 約佔幾十 MB 記憶體。真正吃資源的是窗格裡跑的程式（AI、伺服器、測試）。
- **查看與停止**：`herdr status` 查看是否在執行；`herdr server stop` 完全停止。

---

## 3. PTY：給程式戴上「VR 眼鏡」

PTY（Pseudo-Terminal，虛擬終端）是作業系統用軟體模擬出來的終端機。

- **對 AI 來說**：它以為自己面前有真的螢幕和鍵盤，所以能正常顯示彩色畫面、進度條，接收 `Ctrl+C`、`Esc`。
- **對 Herdr 來說**：它握著 PTY 的另一端，所以能**像真人一樣打字給 AI**（`herdr agent prompt`、`herdr pane run`），也能**讀取畫面上的文字**（`herdr pane read`）。
- **每個窗格都是一個獨立的 PTY**：左邊跑 AI、右邊跑 git，互不干擾。

> 💡 這就是下一站「多 Agent 協同」的基礎：主管 AI 透過 Herdr 打字給小模型、讀取它的回覆。

## 4. 重開機後為什麼能找回版面？

Herdr 有兩層保存：

| 情況 | 保存方式 | 能恢復什麼 |
| :--- | :--- | :--- |
| 暫離後再回來 | Server 一直在執行 | **全部原樣**，包含正在跑的程式 |
| Server 重啟或電腦重開機 | 版面快照存在 `~/.config/herdr/` | 工作區、分頁、窗格配置；有安裝整合的 AI 可恢復對話。其他程式要重新啟動 |
